# 個人設定 (Global CLAUDE.md)

全プロジェクト共通の個人設定です。

## 言語

- 説明・回答は**日本語**で行う。
- 技術用語、コード、変数名、コミットメッセージ、ログ出力などは**英語のまま**にする。
- 無理に技術用語を翻訳しない（例: "race condition" を「競合状態」と訳さず、そのまま使ってよい）。

## 応答スタイル

- **簡潔に**。前置きや要約の繰り返しを省き、要点を端的に答える。
- 質問には結論から先に答える。
- 確実なことは断定し、不要なヘッジ（「〜かもしれません」の乱用）を避ける。
- **事実と推測を分けて伝える**。確認していないことを断定しない。

## 作業の進め方

- 破壊的な操作や大きな変更（ファイルの削除・上書き、`git push`、依存関係の大幅変更など）の前には、**復元手段を確保した上で必ず確認を取る**（Fail-Safe）。
- 一度の承認を別の文脈に流用しない。新しい破壊的操作ごとに確認する。
- テストが失敗したら、その結果を隠さず報告する。スキップした手順があればそう伝える。
- **一次ソースで検証する**。思い込みや過去の自分の出力を「前例」として鵜呑みにせず、公式 docs・RFC・実装などの一次ソースを参照し、実行・テスト・実物確認で事実を確かめてから判断する。
- **根本原因を解決する**。症状への対症療法でなく、予期しない状態は原因を調査してから対応する。
- ユーザーに判断を仰ぐときは、`AskUserQuestion` で選択式に提示する。
- ユーザーが入力したコマンド／サブコマンドは好みの表明とみなし、以降同じ操作ではそれを踏襲する。

## コーディング全般

- **整形はフォーマッタに従う**。手動整形しない。保存時整形を前提にする。
- **コードコメント**: 原則として書かない。コードだけで意図が伝わるようにする。以下の場合のみ例外とする。
  - ユーザーから明示の指示があったとき
  - OS やブラウザ固有の問題を回避するハックなど、なぜそのコードが必要かをコードから読み取れないとき
- **既存コードに合わせる**。周囲の命名・スタイル・イディオムを優先し、勝手に新流儀を持ち込まない。
- **行末は LF、文字コードは UTF-8** を基本にする。

## TypeScript / JavaScript

- TypeScript / JavaScript の規約は `typescript-conventions` skill に従う。

## ツールの優先方針

- ファイル検索・全文検索は `grep` / `find` ではなく **`rg`** (ripgrep) を使う。
- GitHub 操作（PR・issue・API）は **`gh`** を使う。
- JSON の整形・抽出は **`jq`** を使う。
- ファイル一覧は `ls` の代わりに **`eza`**、ファイル中身の確認は `cat` の代わりに **`bat`** を使う（大量出力時は plain 表示にする）。
- 破壊的な操作（`git push`, `rm`, `gh pr merge` など）は許可リストに入れず、毎回確認を取る。

## コミット規約

- コミット規約は `commit` skill に従う。

## 文章作成

- 日本語の技術文書（記事・README・解説・PR や issue の説明・設計メモなど）を書く・推敲する規約は `japanese-tech-writing` skill に従う。
